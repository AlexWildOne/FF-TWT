# Phase 9BB - Planner Assigned Store Scope Continuity

Contract: `fieldflow-planner-assigned-store-scope-continuity-v1`

## Scope

This release restores the operational contract between store assignment and self route planning.

- An active `campaign_locations.assigned_to` record is a direct operational scope signal for its campaign and client.
- `Planear` can therefore resolve the campaign and load the current merchandiser's active assigned stores through the existing `campaign-pdvs` endpoint.
- The scope bridge is evaluated live in `Permissions`, so assignments created before this release work immediately even if the persisted `ScopeIndex` was generated by an earlier build.
- `ScopeIndex` also persists `campaign_location` memberships on future rebuilds, keeping the normalized scope model consistent.
- The rule remains restrictive: only active links with `is_active=1` and `status='active'` contribute planner scope.
- Route creation still requires the same user to have an active assigned PDV in the selected campaign, and self-planned stops remain restricted to stores assigned to the route owner.
- Store assignment is not added to email-recipient inference and does not broaden unrelated client/campaign permissions.
