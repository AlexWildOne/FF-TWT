# FieldFlow 2.2.657 | Cardex & Data Consistency Center 9DW

Contract: `fieldflow-cardex-data-consistency-center-9dw-v1`.
Release chain: 2.2.656 user-certified Stable -> 2.2.657 candidate.

## Rationale and scope

Previous 9DU global audit scanned **existing Cardex ↔ PDV links only** and could not detect stores with no link. It did not consolidate Stocks, Briefing execution questions or form question settings. The 9DW center is a bounded, privileged, read-only audit accessible in **Cardex e Catálogo → Cardex → Centro de Consistência**. It does **not** alter identity rules from 9DN / 9DU, cross-client/project authority, store overrides, original stock import, Shop/Briefing mapping, visit answers or order-suggestion validation 9DV.

## Feature set

- Filters: client, project, candidate retailer (name/tag prefilter, NOT identity authority) and store name/reference/ID. Paginated 30 active PDVs, including stores without any Cardex. Real 9DN retailer identity remains the deciding evidence.
- For each PDV, query the **actual form resolver** with route client/project (or explicit preview scope). Show effective Cardex, *store-level effective assortment* count (base plus revisions/overrides), number of active links, empty assortments, duplicate product references and potential competing Cardex priorities. Where no Cardex resolves but links exist, show precise rejection reason per linked Cardex.
- Dedicated store diagnostics: first 24 SKU/labels/categories in the effective front/order assortment; published briefing questions applicable to **this specific PDV and current date**; newest **published** stock snapshot for the same visit client/project, mismatched retailer-origin evidence, SKU with no Cardex match and explicit links to another Cardex; and a configurable form definition preview that checks the actual question Cardex source (`manual`, `cardex_fixed`, `cardex_auto`) for Frentes, order suggestion and briefing block.
- Missing stock import and absence of briefing questions are informational, never treated as proof of broken associations. Import stock batches remain independent from physical Fronts quantities and from manual order quantities. No bulk edit, retry, auto-publish, re-link or migration endpoint is introduced.
- Form builder hides the fixed Cardex dropdown **only when mode is auto**. In automatic mode it shows a short explanation and a shortcut to the diagnostic center. Fixed and manual modes retain their controls. Existing stored `cardex_id` remains unchanged for backward compatibility but is ignored by runtime in automatic source mode.

## Limits and explicit guardrails

- On each list page only **30** active shops are resolved. Page metrics refer only to that page. The global store count comes from the listing SQL query; it does NOT claim all stores have been tested. The retailer prefilter uses literal name/tags and can undercount ambiguous legacy names; real identity verification uses 9DN authority.
- Route context is the newest route found for that PDV on the selected project, falling back to the PDV card. To check a historical visit, use its actual client/project and date in the live report, not the snapshot of this diagnostic. `BriefingFormBridge` may further reduce questions depending on the selected briefing block settings.
- Stock compares only the **most recent published batch** found for the same client/project/PDV, with at most 1000 rows for line-by-line foreign-SKU sampling; exact total/unlinked count is queried separately. It does not expose all historical stock imports or perform automatic reconciliation. When no matching snapshot exists, the UI says N/D.
- The preview of a form is configuration-based, not a submission. Actual route assignment and conditional question graph may apply additional rules. No email/Excel/PDF is generated by 9DW.
- Read access is restricted to `routespro_manage` capability. No new AJAX endpoints, SQL DML, front/public permissions or background tasks. WordPress/Android production data is unavailable during local build.
