# Phase 7ZE - End-to-End Offline Form Recovery Hardening

FieldFlow 2.2.463 turns the report form into a durable field transaction. The device remains the recovery authority until the canonical submission is acknowledged by the server.

## Audited surface
- Standard form questions and conditional questions.
- Questions generated dynamically from Briefing, including image/evidence types.
- EvidenceFlow child photos, categorized media and generic file uploads.
- Product Cardex and dynamic rows.
- Standalone, Quick Report and Focused Report front-end flows.
- Android/WebView suspension, refresh, weak connectivity, network transitions and delayed responses.
- Device draft, server draft, protected outbox, resumable media and final form ACK.
- Submission history, Cardex reconciliation, route completion and post-commit integration dispatch.

## Zero-loss invariants
1. Every meaningful control change gets a local checkpoint. Answers have both a localStorage mirror and a durable IndexedDB snapshot.
2. Every real photo is stored in the IndexedDB file vault independently of whether the browser can reconstruct `input.files` later.
3. Briefing questions are ordinary schema questions for persistence and recovery. Image questions generated by Briefing use the same durable media path as native form image questions.
4. A draft is a recovery artefact, not the final validation boundary. Form or Briefing evolution never deletes the draft merely because the schema hash changed.
5. Compatible stale schemas rebase to the current form. If a non-empty answered/media key was removed or renamed, FieldFlow raises a conflict and preserves the local copy instead of silently dropping data.
6. Server draft photos are uploaded incrementally. A network drop after photo N never removes photos 1..N already durable on the server, and replacement is per file index only after the new copy exists.
7. A newer server snapshot never deletes local IndexedDB media before valid remote replacement. Failed downloads fall back to the device copy.
8. Delayed weak-network server responses cannot overwrite a newer local checkpoint.
9. The final outbox merges all valid durable draft photos directly from IndexedDB, so Android/WebView DOM rehydration is not a prerequisite for synchronisation.
10. The visible draft and durable file vault are only cleared after `fieldflow-form-ack-v1` confirms the exact mutation and persisted submission ID.
11. Canonical answers are committed before history, Cardex, route completion or external integrations. Post-commit integration work is retryable and cannot invalidate the saved report.

## Media contract
- No FieldFlow fixed-MB ceiling for real photographs.
- 512 KiB resumable chunks for final media transport.
- SHA-256 verification and exact byte-length checks.
- User, device, mutation, field and file-index binding.
- Technical safety envelope increased to 300 media items per form/draft while retaining storage-capacity safeguards.

## Schema changes while offline
Adding optional questions, changing labels, layout or other compatible schema details can rebase automatically. If an already answered question has genuinely been removed or renamed, the item enters `Requires attention` and the protected copy remains available for recovery. This is intentional zero-loss behaviour.

## Database and certification
No database migration is required. Release Manager publication, production manifest SHA-256, licensing, heartbeat, governance, Azure-backed checks and installation certification remain mandatory.
